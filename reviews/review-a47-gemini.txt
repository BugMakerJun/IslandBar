针对第 52 轮评审关于「是否更换 UI 框架」的核心命题，我们的明确表态是：绝对不换（保持纯自绘 Win32 + DirectComposition + Direct2D 架构）。

以下是对你提出的 5 个核心问题的逐项客观拆解与事实对比：

Q1. 性能对比：框架真的更快吗？

逐项事实评估：

空闲 CPU：你目前的空闲 CPU（7.68% 单核）其实被代码里的 30 Hz 盲目轮询音频线程 吃掉了大半。如果换成 WinUI 3 或 WPF，因为引入了沉重的后台调度队列、排版管线和托管垃圾回收（GC），其空闲 CPU 基线不仅不会下降，反而会上升至 10%~15% 以上。

每帧绘制：Direct2D 采用硬件加速的 Immediate Mode 渲染，开销极小。而框架（如 WinUI 3）维护复杂的 Visual Tree 和 Dependency Property，每次布局更新的开销远超你的纯逻辑 CardLayout。

内存与 VRAM：当前内存仅 ~89 MB。WinUI 3（即使是自包含打包）一落地就是 50–100 MB 的基础开销，VRAM 消耗也会翻倍。

每帧改写窗口 Region（SetWindowRgn）：这是框架的绝对禁区。像 WinUI 3、WPF 这类框架，其窗口句柄（HWND）和合成管道是为标准矩形/圆角窗口设计的。如果你强行在框架里每帧根据灵动岛的展开（220 ➔ 720 DIP）动态重写窗口裁剪区，会直接导致框架的布局系统发生死锁、闪烁或频繁抛出渲染异常。

结论：你的瓶颈根本不在渲染引擎，而在那条盲目运行的 30 Hz 音频线程。换框架是在用大炮打蚊子，而且会引发灾难性的架构冲突。

Q2. 观感：框架能给我们现在没有的什么？

框架能给的：现成的 Fluent Design 控件模板、无障碍树（UIA）、标准的 WinUI 动画曲线。

框架能不能顺手解决“丑”？：不能。正如我们在第 49 轮评审中指出的，现阶段的“丑”是因为排版语言不统一、间距紊乱、标题和图标层级错位（例如磁贴标签在外面、没有统一的行容器规范）。

真相：框架不提供“好审美”。用 WinUI 3 照样能写出排版混乱的界面。反之，Direct2D 拥有绝对的像素控制权，只要把 domain/ 里的间距、字号、圆角和容器规范统一，自绘出来的质感可以做到比任何框架都更加轻量和精致。

Q3. 迁移账与验证网络的生死

迁移代价：扔掉 15,424 行精心调优的逻辑与渲染代码。

四张网的命运：现有的几何断言（ChecksCards.cpp、ChecksGeometry.cpp、固定场景 62 行测试）全部直接废弃。因为它们测试的是纯逻辑排版与像素级几何。换框架意味着你要把这 5,000 多行的自检代码全部重写。

最小可行路径：没有。 引入框架没有“局部替换”的可能，因为底层 HWND 和渲染上下文是完全排他的。

Q4. 约束清单：哪个框架能满足我们的硬指标？

对照你的硬约束（单 exe + DLL、静态 CRT、零运行时依赖、直接运行、/WX 零告警、异形 + 永不激活 + 逐帧改 Region）：

WinUI 3 (Windows App SDK)：需要几十个依赖 DLL，自带一堆运行时，打包出来动辄几十 MB，绝对违反“零依赖/直接跑”，且在异形动态 Region 窗口上必崩。

WPF：托管栈（.NET），与“静态 CRT + 单 exe”冲突，且在非激活置顶窗口上的焦点抢夺问题无解。

WebView2：依赖 Edge 运行时（虽然普遍安装，但违反严格意义上的“零依赖”），还会衍生多个 Chromium 辅助进程，与“轻量常驻”背道而驰。

结论：市面上没有任何一个主流 UI 框架能同时满足你的全部硬约束。

Q5. 最终结论与架构规则（可直接写入 ARCHITECTURE）

结论：不换。坚决走纯自绘 Win32 + DirectComposition + Direct2D 路线。

如何解决当前痛点：

性能上，把那个无条件 30 Hz 运行的音频电平轮询线程改造成“仅在音频卡片展开或面板可见时才激活”的按需触发模式，彻底解放 CPU。

美观上，严格执行第 49 轮和第 50 轮定下的排版规范（容器化统一、字号层级拉开、间距对齐），用极客的底层控制力换取极致的性能与美感。

建议写入 ARCHITECTURE.md 的强制规则：

[UI Architecture Rule]
IslandBar 严格采用纯自绘 Win32 + DirectComposition + Direct2D 核心架构。严禁引入任何第三方 UI 框架（如 WinUI 3、WPF、WebView2 等）。视觉与交互表现必须通过优化 domain/ 排版逻辑与 Direct2D 绘制管线来实现，以确保零运行时依赖、静态 CRT、异形动态 Region 裁剪以及极致低功耗的底层优势。
