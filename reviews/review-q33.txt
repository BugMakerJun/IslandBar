【一、"还没学会"现在的确切含义】

从 2026-10-15 起，学习是在 shell 进程里做的：应用注册托盘图标 = 给 explorer 的 `Shell_TrayWnd` 发一条**同步的 WM_COPYDATA**（实测原文 `copydata SENT pid 11936 receiver 0x10146 class "Shell_TrayWnd" dwData 0x1 cbData 1484`），载荷是扩展版 NOTIFYICONDATA（布局已按对照程序校准，+0xC 托盘窗口 / +0x10 uid / +0x14 flags / +0x18 uCallbackMessage / +0x20 szTip / +0x328 uVersion / +0x3B0 guidItem）。我们的模块只装在 explorer 里（**不再往任何应用注入**），读到一条就写一行，进缓存。

所以"还没学会" = **从我们开始听的那一秒起，这个图标一次注册都没有发生过**。典型：NVIDIA 的几个图标在开机时就注册完了，之后一直不动；广播 TaskbarCreated 它们也不重新注册。

现在的覆盖率（此刻卡片 10 格）：ChatGPT（AppContainer，uid 3 / 0x8001 / GUID，**左键已实测可点**）、RazerAppEngine（uid 3 / 0x8001，可点）、explorer 蓝牙（GUID，可点）、Steam（左键它自己不应答）；NVIDIA×3、安全中心、explorer 网络/音量 = 还没学会。

【二、剩下两个缺口，以及我看到的选项】

缺口 1：**已经注册过、之后不再注册的图标**（NVIDIA 那几个）。
  我试过、并已量到的：
  (a) 广播 TaskbarCreated 让它们重新注册 —— NVIDIA 不理。
  (b) 从 explorer 内存里找那条结构体（tag 0x34753423 + 已知布局）：只找到一个真的（explorer 自己的蓝牙图标，字段与缓存完全一致），其余都是噪声。也就是说 shell 并不把每个条目都放在同一种可扫描的堆块里，这条路我在 8.107 就叫它"抽奖"，现在依然像抽奖。
  (c) 查了经典托盘枚举：Win11 上 `Shell_TrayWnd` 底下已经没有 `ToolbarWindow32`（只有 `TrayNotifyWnd`/`ReBarWindow32`/`MSTaskSwWClass` 这些残骸），真正在用的是 `SystemTray_Main` + `TopLevelWindowForOverflowXamlIsland`（XAML）。所以 `TB_GETBUTTON` + TRAYDATA 那条经典路在这台机器上**不存在**。
  (d) 让用户点一次"重启这个应用并学会它"（我们的菜单里加一条）。
  请给顺序与判断：这四条里哪条真的能把这些格子补齐？(b) 有没有我扫描姿势不对的地方（比如它们不在 PRIVATE 堆、而在 XAML 的对象里）？有没有第五条我没想到的（例如把 shell 的托盘 UIA 树里每个图标的身份与注册表条目对上，从而知道"这一格到底还活着没有"）？

缺口 2：**提权应用（任务管理器）**。注册我们能读到（它一样发给 shell），但按压是 Medium → High 的窗口消息，被 UIPI 挡。
  候选：(i) 一个小的提权辅助进程（UAC 一次 / 计划任务最高权限），bar 把 (hwnd,msg,wparam,lparam) 交给它去发；(ii) 整条 bar 提权（我反对）；(iii) 别的办法。
  用户明确说"不要考虑产品级"，所以 (i) 我认为可以做。请判断它到底能不能解决、以及有没有更省事的做法。

缺口 3（可能是真正的答案）：**UI Automation 直接调用 shell 自己的托盘图标**。
  Win11 的托盘是 `SystemTray_Main`（XAML，UIA 可达）。如果在 UIA 树里找到某个图标的元素并 `Invoke()`，那就是 **shell 自己去点它**——不需要知道 uCallbackMessage、不受 UIPI 约束、对提权和 AppContainer 一样有效、行为与真实托盘完全一致。
  这条路我们 8.98–8.101 做过一半（当时的结论：要让 shell 的面板真的出现，XAML 才认为它可交互；alpha 0 会让菜单不再创建，alpha 1 才行），后来在 8.110 跟着"真实点击"一起被删掉了（用户当时的理由是"效果不好"——指移动指针 + 面板闪烁）。
  现在用户说"要的是能实现、不要考虑产品级"。**请判断**：这条路在今天这台 Win11 上是不是最接近"和系统托盘一样"的做法？如果要做，最小验证动作是什么（我认为是：用 UIA 在 `SystemTray_Main` 下枚举图标、对其中一个调用 Invoke，看是否等于真实点击）？它需要 shell 面板"露出来"到什么程度（alpha 1？还是可以完全不露）？

【三、另附：用户点名的文档说了什么（我们已读）】

它是**应用侧**教程，没有"从外部按别人的图标"的办法。它对我们有用的三点：① 回调契约白纸黑字：uCallbackMessage 由应用自己填，通知到达时 uID 进 wParam、鼠标消息进 lParam —— 正是我们从 clash-verge 进程内部量到的那一对消息；② `uVersion` 与 `uTimeout` 是同一个 union，所以 NIM_ADD 里读到的版本多数是 0；③ TaskbarCreated 只发给顶层窗口。

如果你认为这份文档里还有我们漏掉的、能直接用于"从外部按动托盘图标"的东西，请直接指出章节。
