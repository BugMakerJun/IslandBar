0. 它是什么（一句话 + 一张实测照片）

一台 2560×1440、100% 缩放、**原生任务栏在屏幕顶部**的机器上，一个**自己画的顶栏**：默认把系统任务栏
整条隐藏，用我们自己的栏替代它。刚才（2026-10-16 17:36）拍下的静息态
（`IslandBar/captures/ui-now-rest.png`，1010×330 的照片，实际是屏幕顶部 1010 px 宽的一条）：

    桌面那条栏（从左到右）：
    [⌄ 箭头钮] [开始（Windows 标）] [ 胶囊：周五 10月16日  17:36  ☁ 阴 14° ] [⋯ 托盘钮] [4 个应用图标]

照片里没有歌在放，所以胶囊显示的是"日期 + 时间 + 天气"这一条状态；有歌时同一个胶囊显示歌词，
有通知时它变宽显示通知。

1. 界面现状（全部实测，代码里的数字）

  形状（DIP，一个 DIP = 1 px @100%）：
    Collapsed        220×36   静息胶囊
    MusicStrip                有媒体会话时的胶囊（歌词 / 歌名走马灯）
    NoticeStrip               通知条，宽度随内容长出来（0.22 s）
    Hover            720×36   指针停在胶囊上
    Expanded         520×280  卡片（展开态）
    FullBar                   全屏应用在前台时变成整条（盖住那条被系统预留的带子）
  卡片：
    * 三个页面**共用同一张卡**（尺寸/位置/动画都一样，只换内容）：系统面板磁贴页、声音输出页、托盘页；
      互斥、点栏外收起。
    * 展开 0.36 s / 收起 0.24 s，EaseInOutQuint，**从栏后向下滑出**（内容按最终尺寸排版 + 揭示裁剪，
      所以没有逐帧重排的抖动）。
    * 位置：系统面板那张**正中对准系统按钮**、且整体在栏的下方（卡片顶边 50 DIP，岛底边 42 DIP，
      不共享任何一行像素）。
  三处页面内容：
    * 面板：2×3 磁贴（Wi-Fi / 蓝牙 / 飞行模式 / 辅助功能 / 节能 / 实时字幕）+ 音量行（喇叭·滑条·
      输出设备 ›）+ 亮度行 + 页码列（两页，箭头只画在会展开列表的磁贴上）+ 设置齿轮。
    * 声音输出页：输出设备 + 空间音效 + 音量合成器（可滚动，每行一条音量滑条）。
    * 托盘页：**5 列网格**（最多 10 格），格子 = 注册表 ∩ shell 里真的注册着的（本机 9 格）；
      右键四行菜单：打开 / 文件位置 / 应用菜单 / 关闭应用；"结束应用"要按两次（第二下才执行）。
  两端：
    * 左 deck：一个箭头钮（控制原生任务栏）+ 开始钮（打开**我们自己的**开始卡片，不是系统菜单）。
    * 开始卡片：应用列表 + 图钉 + 电源列表（锁定/睡眠/注销/重启/关机，后三种要二次确认）+ 账号头像与名字。
    * 右端：托盘钮（三个点）+ 应用图标行（静止 36 DIP 宽；指针停上去那个按钮展开 **+102 DIP** 并出现
      标题；行会为它让位）。
  字体与图形（DirectWrite 实测）：标题行高 18.7 DIP，次要行 14.7 DIP；图标钮 22 DIP、图标 16 DIP；
  天气/日期条与卡片正文用同一套字。
  材质（可切换主题，`themes\*.txt`）：胶囊的上下双色渐变 + 顶高光、卡片 fill、发丝描边、ink、
  accent，加"玻璃三件套"（阴影 / 颗粒 / 顶高光）。**没有背景模糊**——这是**刻意的**：三条路都实测过
  （DWM backdrop、acrylic、Win2D 区域模糊），代价与不稳定都不划算，记录在 HANDOFF 与 FEATURES 里。

2. 一直是弱点的地方（都是实测过的，不是没发现）

  * 托盘：**不是每一格都能弹出应用自己的菜单**。能拿到回调的（Razer、QQ音乐、clash-verge、
    Wallpaper Engine…）直接弹它自己的；拿不到的（ChatGPT/Codex、NVIDIA 那几格、系统自己的按钮）
    只给我们自己的菜单，并在行里如实标注"应用菜单（本机拿不到）"。用户原话是"**必须全都能弹出
    自己的菜单，跟原生的托盘一样**"——这一条**部分达成**。
  * 托盘按压有几格要等 **300–600 ms**（要隐身显示系统托盘、打开它的溢出面板、等它停稳、再按）。
  * 右键菜单出现在**系统原本的位置**（屏幕右上角），不是指针处——菜单是系统按图标的屏幕矩形摆的。
  * 面板里**亮度滑块 / WiFi·蓝牙开关本身 / 节能模式**没做（磁贴只负责打开设置页）。
  * 歌词是逐行（LRC），**逐字歌词 YRC 没做**；歌的"已播"是栏自己的秒表（总长取自目录），
    中途启动栏时两端会对不上，换歌即对齐。
  * 微信通知只能显示"微信 · 有新消息"（不读内容、不注入，OCR 没做）。
  * 天气/日期条：没有歌时才出现（这条是刻意的，不是缺）。

4. 我要问的（请逐条表态，并给排序）

  Q1 **这一版界面，你们会先改哪三处？** 按"观感收益 ÷ 改动成本"排，并说清每一处的**验收长什么样**
     （最好是一行日志或一个能拍下来的东西）。
  Q2 **一致性**：有没有"同一件事在两处画得不一样"的地方？我怀疑的几处，请判断算不算问题：
     ① 三页共用一张卡的高度，但内容密度差很多（磁贴 2 行 vs 合成器长列表）；
     ② 托盘页是 5 列网格，应用图标行是一维行——同一个"点开一个应用"的两种形态；
     ③ 状态条（日期/天气）与卡片正文同字号，但一个在胶囊里一个在卡里。
  Q3 **反馈**：指针悬停 / 按下 / 等待 / 失败 这四种状态，现在的表现够不够？特别是托盘按压那
     300–600 ms 的等待期（现在只有日志）与"这一格拿不到它自己的菜单"（现在只是菜单里的一行字）。
  Q4 **可读性与可点性**：标题 18.7 DIP / 次要 14.7 DIP、深色胶囊上的 ink 色对比度、22 DIP 的
     点击目标、5 列网格里 22 DIP 的格子间距——在 100% 缩放下够不够？如果用户开 150% 缩放呢？
  Q5 **动画预算**：0.36/0.24 s 的卡片、0.22 s 的通知条变宽、走马灯速度 26 DIP/s、按钮展开
     +102 DIP——哪些是过度设计，哪些还不够？注意约束：这个栏要能在桌面常驻一整天（CPU/GPU 要低），
     且**不允许引入新依赖、不许用背景模糊**。
  Q6 **我们不该动什么？** 这一条对用户最重要：请点名哪些是"看着奇怪但刻意如此"（比如没有背景模糊、
     状态条只在无歌时出现、卡片从栏后滑出、托盘的两次确认），免得我们把它改坏。
  Q7 最后：**你们觉得这个界面漏了什么**？（可以是一个状态、一个交互、一个信息，或者一个该删的东西。）
