用户的指令：「我有一些想法 你们看看行不行实现 就是灵动岛这个左侧留一个按钮 右侧留一个按钮
保持一下对称呢」（附了一张截图：`[⌄] [⊞] 周五 10月16日 20:00 ☀ 晴 11° [⋯]`，全都画在同一个圆角片上）

请判断**能不能做、值不值得做、怎么做最好**，并明确表态。方案先给用户拍板，确认前不动代码。

1. 现在到底是什么样（实测，代码里的常量 + 照片）

一条**圆角片（bar cluster）**托着全部固定控件，从左到右：

    [ ⌄ 系统面板钮 ] [ ⊞ 开始卡片钮 ] ⟨8 DIP⟩ ( 灵动岛 ) ⟨8 DIP⟩ [ ⋯ 托盘页钮 ]

  * 左边**两个**按钮，右边**一个**；每个 30 DIP 见方（`kTaskIconButtonDip` / `kStartButtonDip`），
    按钮之间 4 DIP（`kTaskIconGapDip`），岛与最近的按钮之间 8 DIP（`kTaskIconPadDip`）。
  * 左侧 deck 的坐标**从岛的左边缘向右计数**（`DeckRight = island.left - 8`；index 0 = 开始，
    index 1 = 系统面板钮），所以往 deck 里加按钮不会挪动岛。
  * 托盘钮的左边 = `island.right + 8`，宽 30；**应用图标行紧接在它右边**，再往右到屏幕边距 8 DIP。
  * 圆角片本身两端各多留 4 DIP（`BarClusterFor`：左 = 系统钮左 − 4，右 = 托盘钮右 + 4），
    所以**片子的宽度几乎是对称的**（左 50 / 右 46），**不对称的是内容**：左边两个图标、右边一个。
  * 三张卡片的锚点与按钮绑定：**系统面板卡正中对准系统钮**、**托盘卡片挂在托盘钮上**、
    开始卡片挂在开始钮上——**挪按钮就是挪卡片**。

2. 我们想到的几种改法（请判断并排序；也可以提别的）

  A. **把「开始」挪到岛右侧**（托盘钮右边）：左 1 / 右 2 —— 只是把不对称镜像了一下。
  B. **把「开始」放进岛里**（胶囊左端做成开始钮的样子）：左 1（系统）/ 右 1（托盘），
     开始成为"岛自己的一部分"。代价：岛的左端从此既是形状又是按钮，命中区域与会动的胶囊宽度纠缠
     （岛会从 220 长到 720，开始钮会跟着动）。
  C. **「开始」与「系统面板」合并成一个按钮**（左键开面板、右键/长按开开始卡片）：
     左 1 / 右 1 直接达成。代价：两个功能挤在一个 30 DIP 的钮里，**可发现性**变差（用户现在
     一眼能看到两个不同的图标）。
  D. **把「开始」挪到最右端**（应用图标行之后，屏幕右缘）：岛左右各一个（对称），开始像原生
     任务栏那样待在边上。代价：离岛很远、与"按钮都挂在岛上"的现有设计相反。
  E. **右侧补一个按钮**（例如一个"把栏收起来/隐藏"或"任务视图"的钮）：左 2 / 右 2 也算对称，
     但要新增一个功能，属于扩大范围。
  F. **维持现状**（左 2 / 右 1），只把间距/visual weight 调匀（上一轮 ChatGPT 提过
     "整个顶栏左右重量不平衡，建议共用 36 DIP 基线"）。

3. 约束（不许破）

  单 exe + 一个模块 DLL；静态 CRT、无新依赖；不许背景模糊；`/WX` 零告警；纯逻辑要有断言；
  每片过四张网（两套配置零告警 / 逐字搬动校验 / 自检 1010 条 / 固定场景 62 行 0 差异）；
  验收要能写成"一行日志 + 一张照片"。**这一轮只谈布局与交互归属，不碰功能语义**。
