【一、这个程序是什么（事实，不是设想）】

Windows 11 上替代系统任务栏的"灵动岛"式横条（C++20 + Win32 + D3D11 + Direct2D + DirectComposition，单 exe、静态 CRT、无运行时依赖，实测私有内存 75–100MB）。

它现在做这些事：
  1) 顶栏自己的一条 pill，三种状态（collapsed / hover / expanded）用可中断、继承位移与速度的 spring 动画切换，卡片内部内容 180-200ms ease-out 淡入淡出；窗口是 WS_EX_NOREDIRECTIONBITMAP + Composition SwapChain。
  2) 系统面板卡片：音量/亮度/播放控制等（走 system 开关与 GSMTC）。
  3) 托盘卡片：把系统托盘里的图标画成格子，点一下等于点真实托盘图标（左键=应用自己的左键行为，右键=应用自己的右键菜单），鼠标指针不能动。
  4) 媒体卡片：GSMTC 读会话 + 封面取色 + 歌词（多来源）。
  5) 应用行/任务条：枚举窗口、点击激活/最小化、DWM 缩略图预览。
  6) 通知：读系统 Toast 数据库，把消息与通话显示成通知纸条。
  7) 天气（Windows 定位或 weather.txt 指定城市）、时钟、日期。
  8) 开始按钮（要向 shell 注入 Ctrl+Esc / Win 键）。
  9) 隐藏原生任务栏（ABM_SETSTATE 那条路），自己占位。
  10) 全部纯逻辑（布局、命中测试、动画、状态策略）有一份 900+ 断言的 `--self-test`。

进程与二进制现状：
  * `island_bar.exe`（主程序，静态 CRT）。
  * `island_tray_hook.dll`（**最近新增的第二个二进制**）：装进 explorer 的一个模块，用 WH_CALLWNDPROC 读应用发给 `Shell_TrayWnd` 的 WM_COPYDATA（托盘注册），并把结果写进 %USERPROFILE%\IslandBar\tray_learned.txt；bar 每 5 秒读一次这个文件。两者之间**没有内存交换，只有文件**。
  * `IslandBarSetup.exe`（安装器，payload 是单份 RCDATA，目前只带 exe，带不了 DLL）。
  * tools/ 下若干独立探针可执行文件（geo_probe / thumb_probe / jsonprobe / island_smoke）。

规模与体量（刚测的）：
  * src/ 76 个源文件（37 .cpp / 39 .h），47,876 行。
  * 最大的：selftest/Diagnostics.cpp 8,561 行（903 个 Check）、main.cpp 7,362 行、render/TextRenderer.cpp 4,047、render/Renderer.cpp 1,751、app/IslandWindow.cpp 1,727、core/CardLayout.h 1,604（被 9 个文件包含，92 个 inline 函数）、shell/TrayPress.cpp 934、trayhook/TrayHook.cpp 932、shell/TrayLearn.cpp 784。
  * 构建：CMake + MSBuild，/W4 **/WX**（告警即错误）、/utf-8、NOMINMAX、WIN32_LEAN_AND_MEAN，Release 全量重建 0 告警。
  * 头文件 39/39 有 include guard；包含写成 `"core/Geometry.h"` 形式，包含根是 src/。
  * 测试：没有单元测试框架，靠 903 条自检 + island_smoke + CLI 探针（--tray-surface / --tray-learn / --tray-press N）。
  * 流程（仓库自己的 AGENTS.md）：研究（拿实机数据问外部评审）→ 给用户方案 → 用户确认 → 实现并本地部署（部署到 %USERPROFILE%\IslandBar，不在项目树里，因为项目树下的进程会被降成 LOW 完整性，GUI 起不来）→ 等用户测 → 推送。单实例互斥锁，不能并行跑第二个副本做对照。

【二、已经踩过、必须写进设计的硬约束（都有实测）】

  * 全局 WH_ 钩子（dwThreadId=0）会把 Chromium 的渲染进程打死：把 Clash Verge 的 WebView2 从 12-13 个进程打到 6 个，客户区平均亮度从 56 掉到 0。原因是 RendererCodeIntegrity 拒未签名模块的 pending injection。MyDockFinder 能用全局钩子是因为它的 DLL 有签名。
  * 所以注入只能是"逐个线程、逐个进程、有选择地"装（现在的做法：只装给 explorer）。
  * 注入到别人进程里的模块必须自己 PIN 住（GET_MODULE_HANDLE_EX_FLAG_FROM_ADDRESS|PIN），否则进程退出时导入表会留下悬空指针——这已经崩过 Explorer 6 次、wallpaper64 4 次。
  * 部署目录必须在项目树外，且项目树下的进程被降权（UIPI 会静默丢弃发给 Explorer 的消息）。
  * 日志写在 exe 旁边、逐行 flush——日志量本身是一项成本（现在的日志文件已经 1.2MB+，HANDOFF 800KB+）。
  * 每 5 秒的 tick 里做托盘 harvest（读文件）、每 N 秒写一次内存指标；一帧一帧画的窗口和"事件驱动的世界状态"是同一个线程。
