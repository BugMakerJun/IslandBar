第 53 轮评审请求（2026-10-17 凌晨，IslandBar / Windows 11 26220）——**给灵动岛做"苹果液态玻璃"效果，怎么开发**

用户的指令：「先把灵动岛样式改了 我想要苹果那种液态玻璃的效果 你们三研究一下怎么开发」
（附当前静息态照片：一条深色半透明胶囊，日期+时间+天气，右边三个点。）

请明确表态并给可执行的开发路径。方案交用户拍板，确认前不动代码。

────────────────────────────────────────────────────────────────
1. 目标是什么：Apple 的 Liquid Glass（2025）到底由哪些东西组成

按公开资料拆成四条，**第 1 条是它的灵魂**：

  ① **折射 / 透镜**：它不只是"把背后的东西模糊"，而是让背后的内容**发生位移**（边缘处像一块厚玻璃，
     越靠边折射越强），所以看起来是"液体玻璃"而不是"磨砂"；
  ② **高光（specular）**：沿边缘一圈随形状与指针变化的高光；
  ③ **自适应染色**：从背后的内容取色/取亮度，保证文字对比度（不靠固定黑色）；
  ④ **动态形变**：形状与内容像液体一样跟随交互变形（我们已经有"岛 220→720 生长"的底子）。

**所以它必然要"读到背后的像素"**——这跟我们仓库里一条写死的规矩正面相撞。

────────────────────────────────────────────────────────────────
2. 我们这边的既有事实（都是实测，不是印象）

**现在的材质**（`render/Theme.h` + `render/GlassMaterial.cpp`）：胶囊上下双色渐变 + 顶部高光（gloss）+
发丝描边 + 六段递减的柔阴影 + 确定性噪声颗粒（32 位 xorshift 固定种子）。**完全不读背景**
（除了音乐卡那种"用封面自己造一张模糊图"的做法）。四个内置主题 + `themes\*.txt`。

**背景模糊：三条 API 全试过（HANDOFF 8.86/8.91，探针 `scripts/probe-glass-region.ps1`）**

  | 路 | 结果 |
  |---|---|
  | `SetWindowCompositionAttribute(ACCENT_ENABLE_ACRYLICBLURBEHIND)` | **真的会模糊**（区域外那条边缘能量 16.0 → 3.4），**但窗口 region 不裁它**：把 region 收成胶囊后，region *外面*照样被模糊（7.8 → 3.4）。窗口是 360 DIP 高的透明条 → 直接用会在屏幕顶部糊一条带 |
  | `DWMWA_SYSTEMBACKDROP_TYPE` = acrylic | 返回 S_OK，**画面毫无变化**（这个窗口是 per-pixel alpha + DComp，不吃系统背板） |
  | `DwmEnableBlurBehindWindow` + `DWM_BB_BLURREGION`（唯一文档说"按 region 生效"的） | S_OK，region 内外**都没变化**（7.77 / 53.1）；Vista 的 Aero 玻璃没了以后它只剩返回值 |

**今天的窗口形态**：一条**全宽 360 DIP 高**的置顶窗口（`WS_EX_NOREDIRECTIONBITMAP | TOOLWINDOW |
TOPMOST | NOACTIVATE`），里面一切用 Direct2D 画、经 DirectComposition 呈现；
**胶囊宽度是活的（220 → 720 DIP）**，窗口 region **逐帧改写**；卡片从栏后向下滑出。

**约束**：单 exe + 一个模块 DLL；静态 CRT、**零运行时依赖**；不引入框架/第三方库；`/W4 /WX`；
常驻桌面，CPU/GPU 要低（现在空闲 7.68% 单核——其中一大笔是那条 30 Hz 音量线程，正准备改成按需）；
验收习惯是"一行日志 + 一张照片 + 一组可比数字"。

3. 我们想到的三条开发路径（请判断、排序、补第四条）

  **A. 把 acrylic 用在一个"正好等于胶囊大小"的独立窗口上。**
     既然 `ACCENT_ENABLE_ACRYLICBLURBEHIND` 会模糊但按**整个窗口矩形**生效，那就让那个矩形的形状
     尽量等于胶囊本身：新开一扇**普通 DWM 合成窗口**（不是 NOREDIRECTIONBITMAP/DComp），
     `DWMWA_WINDOW_CORNER_PREFERENCE` 设圆角、系统背板设 acrylic，让 DWM 自己按圆角裁背景；
     胶囊的内容画在这扇窗里，卡片与其余部分留在原来的窗口。
     要问的：DWM 会不会真的按圆角裁 acrylic 背景（而不是糊出四个方角）？这扇窗每帧跟着动画改
     rect，成本多大？层级怎么排（卡片现在是从胶囊**背后**滑出来的）？两套呈现路径（DComp + DWM）
     并存有没有坑？

  **B. 自己抓屏 + 自己做效果链（唯一能做出"折射"的路）。**
     用 **DXGI Desktop Duplication** 或 **Windows.Graphics.Capture** 把显示器画面抓进一张共享 D3D
     纹理（**不回读 CPU**），只取胶囊附近那一条；然后用 D2D 内置效果串起来：
     `Crop/Clip → GaussianBlur → Saturation/Brightness → DisplacementMap（CPU 生成一张透镜位移图）
     → SpecularLighting/自绘描边高光 → ChromaticAberration → Composite(我们的渐变)`。
     要问的：**怎么让我们自己不出现在抓屏里**（`SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`
     对 DXGI duplication 有效吗？还是只能用 Windows.Graphics.Capture 的窗口排除？否则就是自己模糊
     自己的反馈环）？一条 720×60 的抓屏 + 一到两遍模糊，60 fps 下 GPU/CPU 代价多少？
     **只用 D2D 内置效果**能不能做出"边缘透镜"（我指 `CLSID_D2D1DisplacementMap` + 自造位移图），
     还是必须写自定义 HLSL（那就要在构建里加 fxc/dxc 一步——**没有运行时依赖，但多一个构建步骤**）？

  **C. 完全不读背景，继续"画出来的玻璃"，但把"液体感"做足。**
     多层渐变 + 沿边缘扫过的高光 + 内圈亮边 + 形变时的拉伸与内容缩放 + 从主题/壁纸取一个平均色做染色
     （壁纸色可以在启动时用一次 BitBlt 取平均，不每帧读）。
     它便宜、零风险、不动那条规矩，但**做不出"折射"**——请你们判断：用户要的"液态玻璃"里，
     哪一部分是可以靠 C 达成的，哪一部分非 A/B 不可？
